# TermSDR v0.3 — WebSocket Server Mode (Headless)

> Headless backend + web frontend. Control your SDR from any browser.

**Date:** 2026-05-13
**Status:** Approved (Grill Session)
**Goal:** Run TermSDR as a headless WebSocket server with a Svelte web frontend

---

## Decisions Log

| # | Decision | Result | Rationale |
|---|----------|--------|-----------|
| 1 | Deployment model | **Headless mode** (`--headless` flag) | Most useful case (RPi/server without display). Simpler than dual TUI+WS. |
| 2 | Data transport | **Single WebSocket** for everything | Simple to connect, one port. Audio latency (~300ms) acceptable for radio monitoring. WebRTC rejected as overkill for v1. |
| 3 | Audio encoding | **Opus by default**, PCM raw configurable | Opus: ~8 KB/s vs PCM raw: ~192 KB/s. Browsers decode Opus natively. `--audio-format pcm` flag for raw/debug. |
| 4 | Message protocol | **Hybrid** — JSON text frames (state/control) + binary frames with tag byte (spectrum/audio) | Best of both worlds: human-readable control, efficient data. Standard pattern. |
| 5 | Control commands | **Full command set** mirroring TUI's 22 commands | Everything the TUI can do, the web client can do via JSON commands. |
| 6 | Multi-client | **Shared control** — any connected client can send commands | Simplest model. All clients see state changes. Single-user hobby project doesn't need roles. |
| 7 | WS framework | **`axum`** (tokio-based) | HTTP (serve frontend) + WebSocket in one crate. Built on tokio (already a dependency). Best ergonomics in Rust web. |
| 8 | Frontend framework | **Svelte** (TypeScript + Canvas 2D) | Reactive UI for controls, Canvas for spectrum/waterfall. Compiles to vanilla JS (~20KB). 10x faster to develop than Rust/WASM for UI work. |
| 9 | Backend/frontend coupling | **Fully decoupled** | WS protocol is a public API. Anyone can build alternative frontends. Svelte frontend is the "reference client". Protocol documented in `PROTOCOL.md`. |
| 10 | Port & binding | **`0.0.0.0:8080`** default, configurable | `--port` and `--bind` flags. Primary use case is remote access. |
| 11 | Authentication | **None for v1** | Personal/hobby use. User responsible for network security (VPN/firewall). Token auth can be added later. |
| 12 | Spectrum data format | **f32 raw** | Simple, no transformations needed. 240 KB/s at 30fps is negligible on modern connections. |
| 13 | Audio demodulation | **Server-side** | Reuses existing proven pipeline (417 tests). Client stays lightweight. Avoids reimplementing DSP in JS. Bandwidth: 250 KB/s total vs 4 MB/s if sending raw IQ. |
| 14 | UI layout | **Desktop-first**, CubicSDR/SDR++ inspired | Spectrum top, waterfall middle, controls bottom. Click to tune, scroll to zoom, drag to pan. Mobile passable but not optimized for v1. |
| 15 | Settings modal | **Replicated from TUI** as side panel/modal overlay | ⚙️ button opens it. All fields have slider + editable text input for exact values. Same organization as TUI modal (Volume, Squelch, Channel BW, Demod, AGC section, Bandpass section). |

             │                                  │
             ▼                                  ▼
  ┌─────────────────────────────────────────────────┐
  │   WS SERVER (axum)                               │
  │   Thread 4 (replaces TUI in headless mode)       │
  │   ──────────────────────────────────────────     │
  │                                                   │
  │   HTTP endpoints:                                 │
  │   • GET /          → Svelte frontend (static)    │
  │   • GET /ws        → WebSocket upgrade           │
  │                                                   │
  │   WS outbound:                                    │
  │   • Binary [0x01] + f32[] spectrum @ 30fps       │
  │   • Binary [0x02] + opus frames (streaming)      │
  │   • Text JSON: state updates (on-change)         │
  │   • Text JSON: config (on-connect)               │

  │   WS inbound:                                     │
  │   • Text JSON: control commands from clients     │

## WebSocket Protocol (`PROTOCOL.md`)

### Connection

```
ws://host:8080/ws
```

### Message Types

#### Binary Frames (server → client)

| Tag Byte | Type | Payload | Frequency |
|----------|------|---------|-----------|
| `0x01` | Spectrum | `[timestamp_ms: u64][num_bins: u16][dB: f32 × N]` | ~30 fps |
| `0x02` | Audio | `[format: u8][opus_frame_bytes...]` | Streaming (~50 frames/s) |

**Audio format byte:** `0x00` = Opus, `0x01` = PCM f32 raw

#### Text Frames — JSON (bidirectional)

**Server → Client:**

```json
// Sent on connect + on every state change
{
  "type": "state",
  "center_freq": 118100000,
  "sample_rate": 2048000,
  "fft_size": 2048,
  "gain": 30,
  "gain_mode": "manual",
  "cursor_freq": 118100000,
  "cursor_active": true,
  "demod_mode": "AM",
  "channel_bw": 8000,
  "volume": 80,
  "squelch": -60,
  "muted": false,
  "agc": {
    "enabled": true,
    "attack_ms": 10,
    "decay_ms": 300,
    "target_level": 0.3,
    "max_gain_db": 50
  },
  "bandpass": {
    "enabled": true,
    "low_hz": 300,
    "high_hz": 3400
  },
  "vfos": [
    {"id": 1, "freq": 118100000, "channel_bw": 8000, "mode": "AM", "color": "red"},
    {"id": 2, "freq": 121500000, "channel_bw": 8000, "mode": "AM", "color": "green"}
  ],
  "audio_format": "opus",
  "clients_connected": 2
}
```

**Client → Server (commands):**

```json
// Navigation
{"cmd": "set_frequency", "value": 118100000}
{"cmd": "tune", "delta": 25000}
{"cmd": "set_bandwidth", "value": 2048000}
{"cmd": "zoom", "direction": "in"}

// Audio
{"cmd": "set_volume", "value": 80}
{"cmd": "set_squelch", "value": -60}
{"cmd": "set_demod", "mode": "AM"}
{"cmd": "set_channel_bw", "value": 8000}
{"cmd": "toggle_mute"}

// VFOs
{"cmd": "vfo_add", "freq": 118100000, "channel_bw": 8000, "mode": "AM"}
{"cmd": "vfo_remove", "id": 3}
{"cmd": "vfo_clear"}

// AGC
{"cmd": "set_agc", "enabled": true, "attack_ms": 10, "decay_ms": 300, "target_level": 0.3, "max_gain_db": 50}

// Bandpass filter
{"cmd": "set_bandpass", "enabled": true, "low_hz": 300, "high_hz": 3400}

// System
{"cmd": "set_gain", "value": 30}
{"cmd": "get_state"}
{"cmd": "set_audio_format", "format": "opus"}
```

**Server response to commands:**
- Success → broadcasts updated `state` to all clients
- Error → sends to requesting client only:
```json
{"type": "error", "cmd": "set_frequency", "message": "Invalid frequency: must be between 24MHz and 1.766GHz"}
```

### Audio Playback (Web Audio API)

```
WS Binary [0x02] → Opus frames
    ↓
AudioWorklet (decodes Opus → PCM)
    ↓
AudioContext (48kHz, mono)
    ↓
Speaker 🔊
```

- Uses `AudioWorkletProcessor` for decoding in a separate thread (no main thread blocking)
- Jitter buffer: ~200ms to absorb network variance
- Auto-resume `AudioContext` on first user interaction (browser autoplay policy)

## Implementation Plan

### Phase 1: Backend — WS Server Core
> Goal: `termsdr --headless --test` serves spectrum data over WebSocket

- [ ] 1.1: Add CLI flags (`--headless`, `--port`, `--bind`, `--no-web`, `--audio-format`)
- [ ] 1.2: Create `src/server/mod.rs` — axum app setup, router, static file serving
- [ ] 1.3: Create `src/server/ws.rs` — WebSocket handler, client registry, broadcast
- [ ] 1.4: Create `src/server/protocol.rs` — binary frame encoding (tag bytes), JSON state serialization
- [ ] 1.5: Wire spectrum: DSP thread → WS broadcast (binary frame `0x01` + f32 array)
- [ ] 1.6: Wire state: on-connect send full state JSON, on-change broadcast delta
- [ ] 1.7: Modify `main.rs`: headless mode skips TUI, spawns axum server as thread 4
- [ ] 1.8: Test with `websocat` or simple HTML page — verify spectrum data arrives

### Phase 2: Backend — Control Commands
> Goal: Clients can control the SDR via JSON commands

- [ ] 2.1: Create `src/server/commands.rs` — command parser, dispatcher
- [ ] 2.2: Map all JSON commands to existing App state mutations
- [ ] 2.3: Wire control channel: WS inbound → shared state → broadcast updated state
- [ ] 2.4: Error handling: invalid commands return JSON error to sender
- [ ] 2.5: Multi-client broadcast: state changes from any client propagate to all

### Phase 3: Backend — Audio Streaming
> Goal: Demodulated audio streams to clients via Opus

- [ ] 3.1: Create `src/audio/ws_sink.rs` — `WebSocketSink` implementing `AudioSink` trait
- [ ] 3.2: Opus encoder integration: PCM f32 → Opus frames
- [ ] 3.3: PCM raw fallback mode (configurable via command or CLI flag)
- [ ] 3.4: Wire audio: demod thread → `WebSocketSink` → binary frame `0x02` to all clients
- [ ] 3.5: Audio format switching at runtime (client sends `set_audio_format` command)

### Phase 4: Frontend — Svelte Scaffold
> Goal: Web page connects to WS, shows connection status and raw state

- [ ] 4.1: Initialize Svelte + Vite + TypeScript project in `web/`
