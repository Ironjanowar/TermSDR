📻 ¿Qué es SDR?

🔧 Software Defined Radio

En una radio tradicional, la electrónica física (filtros, amplificadores, demoduladores) decide qué frecuencia escuchas y cómo se procesa la señal. Cada radio está "hardcoded" para un tipo de señal.

SDR invierte esto: el hardware solo digitaliza un trozo ancho del espectro electromagnético y lo pasa al ordenador como datos crudos. Todo lo demás — filtrar, demodular, visualizar — lo hace el software.

💡 Analogía: Una radio FM es como una cámara desechable que solo hace fotos con un filtro fijo. Un SDR es como una cámara RAW: captura todo y tú decides en el ordenador qué hacer con la imagen.

🔌 RTL-SDR: el hardware

📦 El dongle USB

El RTL-SDR es un receptor USB basado en el chip RTL2832U (originalmente diseñado para TV digital DVB-T). La comunidad descubrió que podía usarse como receptor SDR genérico reprogramando su firmware.

ParámetroValor
Rango de frecuencia~24 MHz — 1.766 GHz
Ancho de banda máximo~3.2 MHz (estable: 2.048 MHz)
Resolución ADC8 bits
SalidaMuestras IQ (pares I,Q de 8 bits)
InterfazUSB 2.0
Precio~25-35€
💡 Importante: El RTL-SDR solo puede capturar UN bloque continuo de ~2 MHz a la vez. Si quieres escuchar 100 MHz y 433 MHz simultáneamente, necesitas dos dongles. Pero dentro de esos 2 MHz, puedes "escuchar" múltiples señales.

〰️ Muestras IQ: la materia prima

📊 ¿Qué son I y Q?

Cuando el RTL-SDR digitaliza la señal, no te da "audio" ni "datos" directamente. Te da muestras IQ: pares de valores que representan la señal como un número complejo.

I (In-phase) Q (Quadrature)

I (In-phase): Componente "real" de la señal

Q (Quadrature): Componente "imaginario" (desfasado 90°)

Juntos: sample = I + jQ

Cada muestra es un punto en el plano complejo. La señal "gira" en este plano.

💡 Analogía: Imagina que estás mirando una cuerda que vibra desde arriba. I es el movimiento horizontal y Q es el movimiento vertical. Juntos describen completamente la vibración, incluyendo su dirección, velocidad y amplitud.

A 2.048 MS/s (millones de muestras por segundo), el RTL-SDR genera ~2 millones de pares (I,Q) cada segundo. Eso es ~8 MB/s de datos crudos.

💾 Formato de datos IQ

El RTL-SDR envía los datos como bytes intercalados:

Byte:  [I₀] [Q₀] [I₁] [Q₁] [I₂] [Q₂] [I₃] [Q₃] ...
        └──┘       └──┘       └──┘       └──┘
      Sample 0   Sample 1   Sample 2   Sample 3

Cada byte: unsigned 8-bit (0-255), centrado en 127.5
Para obtener el valor real: valor_float = (byte - 127.5) / 127.5

Los archivos .iq o .bin que graba rtl_sdr usan exactamente este formato. Por eso podemos reproducirlos directamente.

🔬 FFT: del tiempo a la frecuencia

🧮 Fast Fourier Transform

Las muestras IQ están en el dominio del tiempo: te dicen qué valor tiene la señal en cada instante. Pero para visualizar el espectro necesitamos el dominio de la frecuencia: cuánta energía hay en cada frecuencia.

La FFT (Fast Fourier Transform) es el algoritmo que hace esta conversión. Es la pieza central del DSP (Digital Signal Processing). 

DOMINIO DEL TIEMPO                    DOMINIO DE LA FRECUENCIA
(muestras IQ)                         (espectro)

  Amplitud                              Potencia (dB)
  ↑  ╱╲  ╱╲  ╱╲  ╱╲                    ↑
  │ ╱  ╲╱  ╲╱  ╲╱  ╲         FFT       │    ┃
  │╱              ╲╱ ╲    ──────────►   │  ┃ ┃
  └──────────────────── → t             │  ┃ ┃ ┃
  "¿qué pasa ahora?"                   └──┸─┸─┸──── → frecuencia
                                        "¿qué frecuencias hay?"

📐 Parámetros clave del FFT

ParámetroValor en TermSDRQué significa
FFT Size (N) 2048 Cuántas muestras toma cada FFT. Más = mejor resolución en frecuencia, pero más lento
Resolución en frecuencia ~1 kHz sample_rate / N = 2,048,000 / 2048 = 1000 Hz entre cada "bin"
FFTs por segundo ~1000 sample_rate / N — cada FFT consume N muestras
Salida 2048 valores complejos Cada valor = magnitud y fase de una frecuencia concreta

📏 De FFT a decibelios

La FFT produce números complejos. Para visualizar, calculamos la magnitud en dB:

magnitud = √(I² + Q²)
potencia_dB = 20 × log₁₀(magnitud)

Los dB son la escala estándar en radio porque comprimen un rango enorme de valores (una señal puede ser 1,000,000× más fuerte que otra) en números manejables.

📊 Espectro y Waterfall

📈 Vista de Espectro (Spectrum)

El espectro es una gráfica en tiempo real donde:

  • Eje X: Frecuencia (MHz)
  • Eje Y: Potencia (dB)

Cada frame es una foto instantánea de "cuánta energía hay en cada frecuencia". Se actualiza ~30-60 veces por segundo.

↑ Simulación de espectro FFT (las señales son los picos)

🌊 Vista Waterfall (Cascada)

El waterfall muestra la evolución del espectro en el tiempo:

  • Eje X: Frecuencia (igual que el espectro)
  • Eje Y: Tiempo (la fila más reciente arriba, las antiguas bajan)
  • Color: Potencia (Viridis: púrpura=débil → amarillo=fuerte)

Es como si el espectro "cayera" hacia abajo, dejando un rastro de colores.

↑ Simulación de waterfall con paleta Viridis

💡 ¿Para qué sirve? El espectro te dice qué hay ahora. El waterfall te dice qué ha pasado en el tiempo. Una transmisión intermitente (como una radio de policía o aviación) aparece como rayas horizontales en el waterfall aunque en el espectro instantáneo la pierdas entre parpadeos.

🔊 Demodulación (v0.2)

🎵 ¿Qué es demodular?

Las señales de radio "empaquetan" información (voz, música, datos) dentro de una onda portadora de alta frecuencia. Demodular es extraer esa información.

ModulaciónUso típicoCómo funciona
FM (Frequency Modulation) Radio comercial, walkie-talkies La información varía la frecuencia de la portadora
AM (Amplitude Modulation) Aviación, radio AM, onda corta La información varía la amplitud de la portadora
SSB (Single Side Band) Radioaficionados, marítimo AM optimizado, usa solo media banda
💡 Para TermSDR v0.2: Lo primero será AM (para aviación, tu caso de uso principal) y FM (para radio comercial). AM es matemáticamente más simple: la amplitud de la señal IQ es el audio. FM requiere calcular la derivada de la fase.

🏗️ Arquitectura de TermSDR

🎯 Principios de diseño

  • Desacoplamiento: Cada fase del pipeline es independiente
  • Sin pérdida: Si el rendering va lento, se descartan frames viejos, no se para la captura
  • Extensible: Añadir demoduladores en v0.2 no requiere cambiar la captura ni el FFT
  • Fuentes intercambiables: RTL-SDR, archivo IQ, o señal de test usan la misma interfaz

⚡ Pipeline de 3 hilos

1

Captura

Lee muestras IQ del RTL-SDR (o archivo/test) en bloques de 2048. Las envía por un canal crossbeam.

~2M muestras/s

2

DSP / FFT

Recibe bloques IQ, aplica ventana, FFT, convierte a dB. Envía el espectro procesado al renderer.

~1000 FFTs/s

3

TUI

Renderiza espectro + waterfall, procesa input de teclado. Descarta frames si no puede seguir el ritmo.

~60 FPS

🔗 Comunicación entre hilos

Usamos crossbeam::channel (bounded) entre cada etapa:

Thread 1 ──► [buffer: 4 bloques] ──► Thread 2 ──► [buffer: 2 frames] ──► Thread 3

Si el buffer se llena:
  • Captura → DSP: descarta el bloque más viejo (try_send)
  • DSP → TUI: descarta el frame más viejo (try_send)

Resultado: nunca se bloquea la captura, la pantalla muestra
           siempre lo más reciente posible.

🎯 Command Palette

Pulsa / para abrir el command palette — una forma unificada de ejecutar cualquier acción de la aplicación, con autocompletado y parámetros.

Cómo funciona

  1. Pulsa / para abrir el palette
  2. Escribe para filtrar comandos (case-insensitive, búsqueda por substring)
  3. Usa ↑/↓ para navegar la lista filtrada
  4. Pulsa Tab para autocompletar el comando seleccionado
  5. Pulsa Enter para ejecutar
  6. Pulsa Esc para cerrar

Comandos disponibles

Comandos con parámetros

Los comandos que aceptan parámetros permiten establecer valores exactos:

/frequency 118.1M → Salta a 118.1 MHz
/channelbw 50k → Establece ancho de canal a 50 kHz
/bandwidth 500k → Establece sample rate a 500 kHz

Sufijos soportados: M (MHz), k (kHz), G (GHz), o Hz sin sufijo.

Gestión de errores

  • Los comandos que requieren un parámetro (frequency, bandwidth) muestran un error si se ejecutan sin valor
  • Valores inválidos (ej: frequency abc) muestran un mensaje descriptivo en rojo
  • El palette se mantiene abierto con el error visible — puedes corregir y reintentar
  • Los errores se borran automáticamente al escribir o borrar caracteres

📦 Dependencias (Rust Crates)

ratatui
Framework TUI. Sucesor de tui-rs. Widgets, layout, estilos.
crossterm
Backend de terminal. Eventos de teclado, colores, cursor.
rustfft
FFT puro Rust, sin dependencias C. SIMD optimizado.
rtlsdr
Bindings Rust para librtlsdr. Control del dongle USB.
num-complex
Tipo Complex<f32> para muestras IQ y resultado FFT.
crossbeam
Canales multi-productor/consumidor para comunicar hilos.
clap
Parser de argumentos CLI. Derive macros para struct → args.
serde + serde_json
Serialización para archivos de configuración JSON.
